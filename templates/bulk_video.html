📦 How Bulk Video Downloading Works

Downloading multiple high-definition YouTube videos simultaneously requires managing bandwidth, memory, and codec processing in parallel. Unlike audio extraction — which demuxes a single stream — video downloads must fetch a separated DASH video track and a DASH audio track, then merge them into a single container using FFmpeg's multiplexing pipeline.

The queue architecture handles this in four stages:

  1. Batch Validation: The client checks each pasted URL for a valid YouTube video identifier (v= parameter or short youtu.be/ path). Duplicate entries are silently deduplicated before the request reaches the server.
  2. Concurrent Scheduling: Each URL is submitted as an independent job with a unique job_id. Up to 3 video jobs run concurrently in the background thread pool. Additional jobs wait in an in-memory queue and start automatically when a worker slot opens.
  3. DASH Stream Merging: yt-dlp selects the best available video codec (H.264 or VP9 at 1080p, 720p, or best available) and the highest-quality audio stream (AAC 128–192 kbps). FFmpeg then muxes both streams into a single .mp4 container without re-encoding video frames, preserving the original bitrate.
  4. Auto-Purge: Completed files are stored transiently and automatically deleted from server storage after 24 hours. No video content is retained beyond that window.

⚡ Concurrency Management

Processing multiple 1080p video streams simultaneously is resource-intensive. To protect stability and keep the service fast for everyone, the server enforces a controlled concurrency limit:

  • Worker Pool: A maximum of 3 active video jobs run in parallel. Remaining jobs queue and start automatically when a worker slot frees.
  • Per-Job Progress: Each queued video shows real-time status: queued → running → merging → completed. Speed and ETA are updated every 2 seconds via Server-Sent Events.
  • Fault-Tolerant Retries: Transient network errors and CDN throttles trigger automatic retries (up to 3 attempts) per job without interrupting other running jobs in the batch.
  • Automatic Deduplication: Submitting the same URL twice in one batch is silently handled — only one download job is created per unique video.

❓ Frequently Asked Questions

How many YouTube videos can I batch download at once?

The default limit is 20 YouTube video URLs per batch on the public instance. If you self-host the application, you can raise this limit by setting MAX_BATCH_SIZE in your .env environment file.

Can I batch download an entire YouTube playlist?

For complete playlists, use our dedicated Playlist Downloader, which automatically expands up to 50 videos from a single playlist URL without manually copying individual links.

Are videos merged with audio automatically?

Yes. YouTube serves many resolutions (720p+) as separate DASH video and audio streams. The bulk downloader always uses FFmpeg to merge both streams into a single .mp4 file so you receive a complete, playable video.

How long are my batch downloads stored?

Downloaded files are automatically and permanently deleted from server storage 24 hours after completion. Download your files promptly. The 24-hour purge is enforced by a scheduled cleanup process verified in the server code.
